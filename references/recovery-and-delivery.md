# 无限画布恢复与交付

## 运行记录

使用 `.canvas-video-runs/<完整UUID>/task-checkpoint.json`；恢复只读取本对话记录的绝对路径，不采用“最近”的文件或同网址标签。

记录下列字段，未知填 null：
- `run_id`、带时区的 `created_at`、`checkpoint_path`、环境实际提供的 `owner_thread_id`。
- 实际 `browser_id`、入口 `tab_id`、画布 `canvas_tab_id`、新标签来源、`project_url`、可见 `project_id`、目标 `video_node_id`/名称及定位截图。
- `phase`、用户生成/下载要求、`images`（文件路径或可见资产 ID、用途、摘要）、`reference_order`（实际图号映射）、完整 `prompt` 和摘要。
- `model`、`reference_mode`、`resolution`、`duration`、`aspect_ratio`、有字段名依据的 `audio_mode`、页面费用原文/单位及估算标记。
- `submission_attempted_at`、`submission_acknowledged_at`、实际 `job_id`、进度/错误、本次结果身份和内容锚点。
- `preview_clicked_at`、`preview_status`、脱敏结果地址、`download_status`、`local_file`、字节数、媒体信息、SHA256、验证结果。
- 人物边走边说任务另记 `speech_mode`、确认的分段对白、实际声音来源、嘴部动作标准、配音替换路线及可见能力依据、短片段验证结果、走动讲话与口型听看验收状态；未经验证的能力填写未知。
- 多段任务逐段记录唯一名称/节点ID、确认对白、音频路径或资产、音频实测时长、参数、受理/完成状态与输出文件；合成记录片段顺序、时间轴起点、静音/换音理由、导出参数及最终节点，避免续做时重复计费或错接素材。

不保存密码、验证码、Cookie、签名 URL 查询令牌或其他项目正文。写回前核对运行/项目/素材归属；时间戳不是 job ID。

## 断点与冲突

- 新标签属于另一任务时不抢占，不换浏览器绕过归属。绑定句柄失效时，仅查原 ID 是否还存在；确认关闭后才建立替代标签，打开已记录项目，并记录替换关系。
- 等待、重连、用户操作后，重新读取目标项目、视频节点、参考映射和提示词。若变化，暂停本次写入，保存证据，不能反复覆盖草稿。
- 独立标签不能保证服务端草稿隔离；真实观察到覆盖才协调串行操作。共享资产列表出现别人的作品不等于本次内容被覆盖。
- 提交后未知：先查看目标节点任务状态与错误，再检查页面提供的本项目任务/结果记录。已受理就等待或找回，不新建项目重跑。教程的剪辑高手右侧历史不适用于这里。
- 明确失败：保留错误、已用参数和记录。修正输入可以准备，但再次付费提交须已有重试授权；不无限重试。登录、配额或权限问题按实际原因处理。
- 预览空白：先点击对应结果；必要时重选同一结果一次并短等。内容归属可靠但网页无法播放时，可下载后核验，同时保留网页预览失败状态。

## 结果下载与验证

只要求画布预览时不追加下载；要求交付文件时：

1. 在已匹配的结果节点/预览中找实际可见下载入口，必要时查看该对象工具条或菜单；不猜固定按钮位置。保存下载与本次结果关联。
2. 正常下载进行中继续等待。HTML 页面壳、空文件或浏览器错误都不是视频下载成功。
3. 在本次授权包含下载且当前工具允许的前提下，普通下载失败可从该结果可见下载动作实际暴露的真实媒体 URL 本地保存；只操作该结果，不加认证头，不取隐藏状态，不改浏览器保护，不调用后台接口。执行权限被拒按真实限制报告，不能把它当网页故障规避。
4. 签名地址只作临时下载输入，不写入报告、checkpoint、持久脚本或日志。没有真实地址则继续检查本结果的可见入口；仍不可得时交付项目/预览位置并说明缺项，不猜 URL 或生成另一条。
5. 文件名使用内容简名和 run_id，保留旧文件，下载至唯一临时文件。用实际下载来源关联，不用下载目录最新 MP4 认领。
6. 核对文件非空且不是 HTML，使用 ffprobe 检查真实视频流、正时长、尺寸与目标相符；用 ffmpeg 全片解码验证完整性。是否要求音轨取决于本任务声音要求，静音任务无需强制音轨。
7. 核对实际画面开头/中段/结尾与节点结果、人物、产品和主要镜头对应；对白或无音乐要求须实际听音才能报告听证通过。人物任务按 SKILL.md 的“边走边说”默认要求同步听看讲话片段，确认人物行走时也在讲话、讲话镜头中嘴部自然运动，不要求逐字对齐；闭嘴走动加旁白不能判为通过。结构/解码检查不能替代内容与声音验收。
8. 验证通过后不覆盖地改为最终文件名，记录大小、SHA256和真实路径。任何验证未完成，分别说明，不能泛称“全部通过”。工具缺失先检查现有替代工具，不擅自安装软件或拿文件扩展名代替验证。

交付时区分生成成功、网页预览状态、本地下载状态和质量差异。质量不符时提供具体问题和改稿建议，不自动追加付费生成。

## 多场景成片的补充记录

每段记录reference_mode=images_plus_audio（无对白时images_only）、图片实际引用编号、前段末尾姿态/方向/道具/构图、下段起始状态、转场触发动作及对白停顿位置。reference_order记录图片及本镜音频的实际编号；保存音频asset_id、模型、音色准确名称、实测时长及文案版本，具体私人音色写私有记录；旧reference_video_node_id标记为历史，不沿用到新生成。

记录字幕入口、字幕文本/时序检查结果、背景音乐关闭状态与听音验证、最终拼接顺序。完整交付包含营销智脑导出的有对白和字幕、无背景音乐MP4；保留原始分段用于追溯，不能用分段替代约定整片。交给剪映的待办只有清晰度与音乐。所有声音与嘴部动作状态分别标记passed/failed/pending，不以文件技术通过替代内容通过。

## 用户脚本来源

checkpoint另记用户原稿路径或本任务消息锚点、脚本版本、口播确认状态、适配稿路径和修改说明。区分用户原文与执行补充，正文私有保存、不进入公共仓库。恢复时按已确认版本继续，不依据新旧文件名猜脚本、不重复索取已提供稿件。

## 素材溯源

每段保存shot_id到asset_id/version/hash、character_id、allowed_uses/excluded_uses及实际图片/视频编号的映射。原始身份参考、目标服饰、场景与其他人物分开登记。素材总账与当前任务引用清单分离，上传/已引用/已生成分别记录；依据参考asset-management.md管理。


## 口播画面质量失败后的恢复

用户指出有声闭嘴时，将mouth_activity_qa标为failed，撤回整体通过结论，保留旧文件和技术检查，不把它们当当前验收。按[speech-activity-qa.md](speech-activity-qa.md)记录逐句修复及证据；最终文件必须单独版本命名，不能覆盖用户已查看的旧版。
