# 实际执行：按证据操作，逐阶段检查

本参考依据2026-10-01的人物花园水果样片实测。已验证：数字人素材复用、参考图上传、多场景动作生成、指定音色配音、画布内置剪辑及导出。历史未验证：指定音色下的严格口型同步路线。当前默认仅要求讲话镜头有自然嘴部动作，严格同步不再是交付门槛。旧样片是走动画面加旁白，不满足用户后来明确的边走边说要求，不能当成合格模板照抄。历史价格、分辨率、按钮和耗时不是永久承诺。

## 1. 开始前先确定这六件事

1. 读取本任务checkpoint，明确续做项目、目标节点、完成阶段；恢复已有任务不另建项目，不重复提取文案或生成已完成音频。
2. 先核对用户提供的脚本及其中的口播、分镜、提示词，保留原稿并记录版本。没有脚本则等待，不能用一键追爆或参考片文案自行补齐。已有确认稿直接续用。整理指定人物、声音、素材、画幅和预算；默认只配置生成参数、核对素材绑定，分镜/提示词原样执行；仅无损修正实际引用编号并记录。时长不足时先说明模型限制与可行参数，涉及拆分分镜先确认，不能删句或强行加速；实质文案/创意修改先获得用户确认。只有用户本次明确另行委托写稿或改稿，才进入内容创作流程。
3. 记录音画目标为“人物边走边说，嘴部自然运动即可”，默认先合成指定音色音频，再引用音频生成视频；后配音仅是明确选择后的恢复路线。未证实某路线可用时先检查页面说明/入口，不能以“全能参考”“原生音频”等名称替代验证。
4. 模型必须读回 `Seedance 2.5特价版` 完整名称。用户指定声音时，还须核实该路线能保留该声音。无法同时满足时说明具体能力冲突，不能自行用默认声线或旁白代替。
5. 将确认稿按句分段，记录每段对白、预计/实测音频时长、动作、场景和顺序。不要让30秒画面承担超过30秒的对白，不在句中切断语音。先完成一个计划片段的嘴部动作和声音验证，再扩展后续片段。
6. 用户要求“先做一条看看”时，只交付一条样片，等用户认可后才能批量生成其余链接。清单有多条链接本身不等于允许立即全量消耗算力。

## 2. 人物和场景参考

先按asset-management.md核对素材用途。以下“保持服装”只指任务已确认的目标服装，不能将仅供身份参考的原照片服饰带入新视频。用户另供服饰、场景及其他角色时分别绑定；缺项等待，不用旧照片背景代替。

- 用户指定复用数字人时，先从当前可见资产选择，核对完整名称、缩略图和服装；例如用户指定花园形象时，不能误选同人物的室内形象。旧任务的具体人物不强制套到新任务。
- 已有资产可从画布/我的资产引用。需生成场景图时，以已授权人物参考保留脸型、年龄、发型、服装，场景和物品服务于文案，不凭空换人物。生成或上传后先看实际图再使用。
- 实测复用人物首帧作为身份参考，并制作同人物的室内水果桌参考有效；这只证明视觉参考可用，不证明已获得人物声线或口型驱动能力。
- 给每段建立图号映射。后续段通过“添加视频引用 → 画布”复用已上传图片；以缩略图对应的当前图片1/2为准，不按文件名或画布位置猜编号。

## 3. 提示词写法与输入检查

用户来稿不按模板强制改写。以下供获得明确创作/优化授权时使用；每段编写内容包括：实际图号用途、身份与服装一致性、缓慢自然行走、正面/侧前方可见嘴部的运镜、逐字对白、自然可见的说话嘴部动作、连续声线、场景切换及用户要求的音乐/字幕限制。

获准编写或优化时使用的结构（不自动追加到用户原稿，填写真实内容后提交）：

> 图片1用于人物身份，图片2用于场景。同一人物保持已确认的外貌与服装，沿场景中的路径自然缓步行走，镜头从侧前方平稳跟拍，嘴部清晰可见。行走时亲口说：“【该段确认对白】”。人物的嘴唇与下颌必须随对白自然开合，形成真实可见的说话口型，每句实际配音期间持续有自然说话动作，具体字音无需严格对齐。声音来自画面中正在说话的人物，不能只有画外旁白，不能闭嘴行走。允许自然停步和简单手势。切镜后人物与音色一致。无背景音乐，保留人物对白。此生成片段不烧录字幕，成片阶段在营销智脑统一制作字幕。【如指定音色，填已核实的实现方式】。

- 在获准使用上述模板时要求模型生成行走、人物对白及嘴部动作，并在已授权的首段中验证结果。没有独立口型按钮，不是删掉说话提示或自动退回旁白的理由；但也不能因写了“同步”就宣称输出必定同步。用户指定声音时先执行audio-reference-workflow.md，核对音频绑定和生成原片效果；不能仅凭音频引用入口就声称保声或口型成功。不能沿用旧样片的“无人声、不要做持续张嘴对口型动作”。无音乐写成“无背景音乐，保留人物对白”。
- 实测视频描述是富文本编辑器：普通fill或包装层paste可能无报错却没有完整写入。先用当前工具支持的输入方法；读回不符时，在正确文本框获得焦点后使用已支持的剪贴板粘贴。只在已聚焦描述框中全选，不对整页全选。
- 长文逐字输入可能超时后只留下半段。每次输入后读取完整可见文本，核对长度/全文、开头、结尾、各段对白、参考图号。超时后先读现有文本，再决定替换，不能盲目追加第二遍。

## 4. 可点击不等于点击成功

- 浮动编辑区可能超出视口或被其他节点遮住；工具返回click成功不证明页面受理。截图确认按钮实际可见，必要时重置视图、缩放或移动目标节点，然后重新读取页面状态。
- 实测拖节点主体可以移动，拖标题不一定生效。坐标只从本次新截图取得，不能复用本参考或旧任务坐标。
- 先给节点改为有顺序的唯一名称，如 `A_场景简名_时长`、`B_场景简名_时长`、`人物配音_主题`。实测入口是目标节点右键 → 重命名 → 节点名称 → Enter。以名称、可见节点ID和内容定位，不以“第一个视频”定位。
- 切换模型会重置分辨率和时长：实测特价版与正价版切换后30s变成10s，正价版还可能变480P。每次切模型都重新读回模型完整名称、全部参数、引用顺序和提示词；查询完恢复原配置也要核对。
- 读取操作后出现短暂旧快照时，再做一次状态观察；不要以一次旧快照判失败并重复创建、上传或提交。

## 5. 提交与等待

提交前逐项满足：正确项目和节点；指定特价模型；图号与素材对应；完整对白和边走边说提示；默认生成提示中明确可见嘴部动作及人物对白；如使用指定音频，其文案/音色/时长与视频节点实际引用已核实；时长足够；实际分辨率/比例；费用单位和总额估算；本次授权范围。缺关键项先修复，普通已授权生成无需再问常规确认。

- 实测页面70算力/秒，30秒估算2100、两段估算4200；这不是实扣账单，执行时必须重新读取费率。短验证片段和额外尝试也计入预算。
- 只点击提交一次，分别记录尝试时间、受理时间和可见状态。出现“视频生成中”才视为已受理；只有按钮点击记录不能证明开始生成。
- 特价版两段30秒实测约17–18分钟后得到结果。长等待不能直接判定失败，也不能反复提交、刷新或取消重建。按当前工具允许的间隔等待并简述进展，不承诺固定完成时间。
- 状态长期未变化时，检查目标节点及历史记录。历史里的“查看”可能提示“暂无可预览内容”，不是完成；用提示词和内容确认条目归属，不按第一条或最新条认领。
- 明确算力不足等失败：保存错误和参数，等待用户充值/修复及已有重试授权；不循环重试。用户明确表示已充值并要求继续时，可以继续原任务，无需再问一次。

## 6. 音频与剪辑：先引用指定音频生成，后配音仅为恢复选项

先执行[audio-reference-workflow.md](audio-reference-workflow.md)。生成原片音色与讲话效果已获认可时保留原音轨，以下静音/换声说明只适用于明确授权的修复，不能作为默认生产顺序。

画布可生成音频：实测音频节点中有“文字转语音 → 音频合成”、语言和“我的配音”。实测支持从“我的配音”选择已有音色；实际使用时核对名称，语速/音量/音调按本任务配置，不把历史1.1倍速写死。

选择音频节点后浮动“音频功能菜单”有下载、裁剪、变速。音频节点可能没有可读的HTML audio元素，使用可见下载按钮即可；不要为找地址读取隐藏状态或接口。

需要拼接时优先画布左侧“剪辑”内置编辑器：

1. 打开“画布素材”，按顺序点击各段“添加…到时间轴”。等待素材真正入轨，检查总时长与画面顺序；刚点击时快照可能尚未更新。
2. 竖屏成片核对9:16。实测先加竖屏视频会自动匹配比例，但仍须读回；先加音频时可能默认16:9。
3. 加号添加音频实测会接在整个时间轴末尾，并非自动从0秒开始。必须检查波形起点、实际播放与总时长，必要时将音频拖回正确位置；源素材“入点0”本身不能证明它在总时间轴0秒开始。
4. 实际配音播放期间，人物必须持续有自然说话动作。允许将原视频人声静音，再添加指定音色合成的同一文案，新配音必须落在可见说话区间内，仅不要求具体字音与嘴型逐字一致。保留用户认可的画面和动作，合理安排音频到对应讲话片段，确保文案不丢失、不截断、无双重人声和未要求的背景音乐。不能为追求嘴型匹配反复生成已认可画面；若配音长到无法容纳、必须改变已认可画面时说明具体时长差再确认。
5. 检查拼接处不切断词句、不重复对白、不出现黑屏或无画面长尾。若音画略有时长差，依据实际语句与画面决定裁剪，不盲用最短时长截断讲话。
6. 实测关闭剪辑器后，未导出的编辑内容没有保留。加入素材后先完成导出，不随意关闭去做别的操作；一旦必须关闭，先保存分段顺序与时间信息，不能声称草稿已保存。
7. 导出前核对标题、分辨率、帧率、MP4以及“包含音频”。可“导出到画布”再从结果节点下载；显示100%或新结果出现后核对输出，不以开始导出当成完成。
8. 导出的新视频节点可能与已有节点重叠，导致点击选中旧视频。可移开遮挡节点，核对新节点完整文件名、约定总时长和工具条所属对象再下载。选中节点后“视频功能菜单 → 放大”实测可打开完整预览。

## 7. 交付与批量门槛

- 每段输出与最终合成分别保留；从明确下载动作取得文件路径，不能用下载目录最新文件猜归属。最终交付路径单独写出，让用户能直接找到视频。
- 核对真实媒体信息和完整解码，逐句检查实际配音的完整时段、起止及切镜，首中尾抽帧只能辅助。分别检查行走、自然嘴部动作、完整文案和指定音色；不检查逐字嘴型，但每句配音全程须与可见说话区间对应；有声闭嘴判失败。只有用户明确提出严格同步时才启用更严格的听看核验。
- 画布预览成功、下载成功、文件技术通过、人物动作通过、口型通过、用户试听确认是不同状态。工具不能听音时如实留待用户确认，不宣称全部验收完成。
- 人物讲话段全程闭嘴或音色不符时，将结果标为未达标，说明具体问题；不能把它包装成已满足要求，也不自动追加付费重做。
- 仅修改skill不生成视频。新规则生效不表示边走边说路线已经实测成功；批量前仍须通过首段/样片验证及用户要求的效果确认。

## 8. 当前项目的成片分工与新证据

以SKILL.md的制作分工为准：默认无背景音乐，营销智脑完成剪辑、转场与字幕，剪映只承担清晰度和音乐。先检查当前字幕/包装入口，核对准确文案、时序、位置和音轨；没有完成这一步不能声称交付了完整字幕成片。包装模板若默认带音乐，必须关闭并听音复核；不能靠静音整条视频去掉音乐，因为会损失对白。

2026-10-01追加10秒样片：特价版原片10.05秒、720×1280、24fps，完整解码通过；连续帧可见嘴部开合，但未听音确认准确对白、声音与逐字同步，腿部未完整入镜，不能宣称行走与口型全部通过。旧的指定配音样片和新的原生声音试片不是同一验证路线。

同日网站能力中心可见“视频超清增强”，列有720p/1080p/2k/4k、200MB以内且小于50s、页面2算力/秒。只验证了入口和选项，没有验证增强结果。它不是模型原生高分辨率证明；当前分工明确交由剪映做清晰度，因此不默认在网站提交增强。只有用户另行要求网站增强时，再检查当前限制和费用。

分镜/拼接参照creative-direction.md和sequential-continuity.md。使用图片与指定音色音频参考；旧教程视频引用方式已被用户成本要求覆盖。历史视频仅作查看和剪辑素材，不再绑定为生成参考。


## 后配音时段检查

后配音与重剪必须先执行[speech-activity-qa.md](speech-activity-qa.md)。技术通过不能替代逐句口播画面验收。禁止因配音比镜头短而统一从第2秒或第3秒开始铺音频；禁止把有声闭嘴归为无需严格对口型。
